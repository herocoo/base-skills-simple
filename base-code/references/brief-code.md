## 执行纪律

1. **严格按计划**,不扩展范围,不做计划外重构,不动其他 group 的文件。
2. **测试驱动(红 → 绿 → 重构)**,每个任务:
   - 红:先写测试(一个测试一个行为,名字说明行为,用真实代码,只对外部依赖用 mock,断言行为而不是 mock 的调用次数),运行并确认**失败**,且原因是功能缺失,不是语法、导入或配置错误。一跑就通过说明测的是已有行为,改测试。
   - 绿:写让它通过的最小实现,再跑本任务测试和同模块已有测试,全部通过。
   - 重构:只在全绿后做(去重复、改名),保持全绿,不加行为。
   - 先写了实现再补测试 → 删掉该实现,从测试重来,不留作"参考"。
   - 例外(不必先写测试):纯配置、文档、脚手架、生成代码。计划注明本 group 无自动化测试(用户已确认)时整体跳过,`checks` 的 tests 填 `none`。
3. **按任务提交**:每完成计划里的一个任务就提交一次,message 用计划里写明的 `feat(...)` / `fix(...)`。提交后把该任务标题的 `[ ]` 改成 `[x]`(这是唯一允许的计划修改,用于断点续作)。不积攒零散提交。
4. **命令输出截断**:构建与测试输出超过 50 行时只取末尾 50 行。Maven 用 `-q`,Gradle 用 `--quiet`,npm 用 `--silent`。
5. **收尾验证(必做,后续审查不再编译)**:全部任务完成后,在 `{{workDir}}` 跑一次**全量**测试与类型检查:
   - backend:Maven `mvn -q test`(多模块且仅少数模块有变更时可用 `-pl <模块> -am`);Gradle `gradle test --quiet`。
   - frontend:`npm test --silent`(watch 型脚本加 `-- --run` 或设 `CI=true`);**另跑**类型检查,按顺序选第一个可用的:`npm run type-check` → 依赖含 `vue-tsc` 时 `npx vue-tsc --noEmit` → 有 `tsconfig.json` 时 `npx tsc --noEmit` → 都没有记 `types=n/a`。
   - 验收以计划写明的条件为准;计划注明基线已有错误的,按"**不新增**错误"判定。
   - 失败就修复后重跑,修复归入所属任务的提交;同一失败修 2 次仍不过,返回 `blocked`,**不得返回 done**。
6. **收尾**:`git status --porcelain` 必须为空;剩余改动并入所属任务补提交。
7. **不询问用户**。需要用户裁决的情况一律 `blocked` 返回,写明已落地的提交。

```
tdd: <亲眼看到先失败再通过的任务数>/<需先写测试的任务总数>
reason: <done 时留空;blocked 时一行原因 + 建议动作>
```
