# 任务单:代码探索 {{group}}

> 主会话把 `{{变量}}` 替换成实际值后,把全文作为委派消息直接发给 base-explorer(不写文件),或内联执行。

探索 `{{group}}`(type=`{{groupType}}`)的现有代码,为技术方案提供事实基础。**只读,不改任何源码。**

## 基准

- 读文件、执行命令:一律在 `{{workDir}}` 内。
- 报告写到 `{{reportPath}}`(绝对路径,在 `.base/dev/` 下,不在源码仓库里)。
- 不写 `flow-state.json`,不运行编译或测试,不提交。shell 只用于只读命令(git log/ls-files、目录列表等)。

## 输入

- 本次需求涉及的能力点(`focus`):
{{focus}}
- 上游 API 契约(有则读,无则跳过):
{{apiContracts}}
- 产品文档:`{{prodDesign}}`(无则写"无")

## 任务(工具调用预算 ≤ 12 次)

1. **工程概况(1–2 次)**:读构建文件(`pom.xml` / `build.gradle` / `package.json`)的关键段,取框架与主要依赖版本、模块划分、包结构。
2. **相关现有实现(3–6 次)**:按 `focus` 在代码里搜索现有同类功能或相邻模块,记录入口、核心类、分层位置。命中的文件只读关键行段,每次 ≤150 行,**不整文件读大文件**。
3. **既有约定(2–4 次)**:挑 1–2 个同类功能作为样板,确认命名风格、异常处理、日志写法、DTO/VO 分层、测试位置与框架、Mapper/Repository 写法。
4. **可复用与缺口(1–2 次)**:列出可复用的工具类、基类、中间件;确认方案需要但仓库里没有的能力。
5. **写报告(1 次)**。

## 约束

- **只报告事实**,不写"建议采用 X 方案";代码里找不到依据的话不写。
- 不粘贴源码块(签名 ≤3 行),引用写 `文件:行号` + 一行说明。找不到同类实现就写"仓库内未发现",不臆测。

## 完成标志

只输出这三行:

```
report: <报告绝对路径>
lines: <报告行数>
gaps: <缺口条数>/<待确认问题条数>
```

无法完成时只输出:`result: blocked` 与 `reason: <一行原因>`。
